# GitHubからの再開プロンプト

以下を新しい開発作業へ渡してください。ローカルの引き継ぎファイルや以前の会話は不要です。

容量優先モードの続きを行う場合は、下記のmainをfeat/recording-economyに読み替えてください。Windows CIとNVENC/MKVの実録画検証まで完了し、main・Release・PC常設版への反映はまだ行っていません。

```text
https://github.com/yuuki-ama1015/obs-quick-record のmainから開発を再開してください。
まずAGENTS.md、README.md、docs/CLOUD_HANDOFF.md、docs/design.md、docs/testing.mdの末尾を読んで、最新コード・Release・実機で未確認の条件を確認してください。

既定はAlt+R、選択画面内のEnter確認、OBS前面時の開始禁止です。OBS起動アシストが起動したOBSは正常終了後に閉じ、録画エラー/結果不明では保持します。既存OBSやユーザーが表示したOBSを勝手に終了しないでください。設定/音声/出力解像度はそのまま利用します。
obs-auto-stopは独立したまま変更・リンク・固有API依存を作らず、録画はOBS標準イベントで共存させてください。設定ドックを開く合意済み導線と、未導入時の非表示は維持します。OBS本体も改造しないでください。

最新の未確認条件から、利用可能な環境で実行できるものを進めてください。実機条件を自動テストだけで合格にせず、Windows/MSVC/GUIが使えない場合は限界を記録してください。OBS 32.2.2のSource ID/setting keyはソースで確認し、OBS参照とQtスレッド/終了時の解除を守ってください。

進捗を小さいGitコミットで管理してください。「GitHubに反映」の指示は配布ZIPのRelease公開も含みます。最上位モデル使用時はサブエージェントを併用しないでください。公開物のハッシュを確認してから、ユーザーが承認した作業データだけを整理し、導入済み本体・設定・自動起動登録を保持してください。私的なメモ・個人設定・録画は公開しないでください。
```
