# 高速化・軽量化の優先修正（2026-10-19）

対象は0.1.4からの作業ブランチ `feat/performance-hardening`。優先順位は、昇格・起動依頼の安全性、継続的なファイル肥大、重複I/O、録画準備の反復処理、表示の不具合とした。main・Release・PCへはまだ反映していない。

## 今回の修正

- 導入：管理者確認後にユーザー書き込み可能なスクリプトを再読しない。すでに読み込んだコピー用関数だけをEncodedCommandで渡し、コピー元DLL・localeは確認待ちから終了まで読み取りロックする。診断ファイルも開いたまま保持し、取消・失敗時はハンドルと一時ファイルを解放する。起動アシストの導入・起動は従来どおり通常権限。
- 起動依頼：同じディレクトリの一時ファイルへ完全な内容を書いてから公開する。既存ファイルの置換もアトミックに行い、例外時は一時ファイルを削除する。PID・期限・一度だけ消費する検査は維持。
- ログ：256KiBで切り替え、旧ログは1世代だけ。旧版で大きくなったファイルも末尾256KiBだけを残し、1メッセージは4096文字までに制限する。現在のログは最後の1メッセージ分だけしきい値を超え得る。
- 設定：実際の保存先の内容と一致する場合、書き換えない。メモリ上の成功キャッシュだけには頼らず、外部変更・削除・保存失敗後の再試行を扱う。設定画面の保存コールバックは参照する所有者を明示する。
- 初回応答：FINISHED_LOADING後、最初のイベントループで依頼を確認する。見つからなければ従来の500ms周期へ戻し、60秒の期限と終了時の解除を維持する。
- ウィンドウ録画：準備中はHWND/PIDと表示状態を軽く確認。OBSソースが取得したタイトル・クラス・実行ファイルの照合と250msの安定待ちは維持し、重いOBSウィンドウ探索は準備開始時と録画開始直前に行う。
- ホバー：まず表示状態とGetWindowRectで絞り、その候補だけでDWM・タイトル・プロセスの問い合わせを行う。describeの二重呼び出しを解消する。
- 範囲選択：ドラッグ中の物理座標が変わらなければ矩形と説明を再計算しない。画面外・異種DPIの座標変換やEnter確認は変えない。
- REC表示：文字列に必要な大きさが変わった場合だけサイズを調整し、右端へ置き直す。100分・1000分になっても右にはみ出さない。

## 検証の範囲

インストーラーは通常権限の専用一時フォルダーにコピーする隔離テストを使う。実際のUACを承認する試験や、署名済みインストーラーと同等の全体監査をしたものではない。日本語・空白・引用符を含むパス、確認待ち中のコピー元変更拒否、失敗診断・取消・再試行を確認する。

起動アシストの自己テストは通常のWindows環境で成功。制限環境では一時ファイル移動が拒否されたため、制限環境の結果を実環境の動作不良とは扱わない。専用一時フォルダーを使い、常設版やユーザー設定を更新しない。

Windows CIでは実際のQt/libobsを使う既存9テストに回帰条件を追加する。録画準備の重い照合回数、最終照合失敗時の開始禁止、設定の同一内容での更新日時保持、外部変更・削除後の保存、100分以上のREC表示を含む。最新のCI結果はdocs/testing.md末尾に記録する。

処理回数や書き込みの削減を、実機のCPU使用率・メモリ・起動時間の改善率と同一視しない。実録画、各DPI、各キャプチャ方式の再受入と、同一条件での性能比較は未実施。

## 次に判断する項目

起動アシストはすでに多重起動防止ミューテックスと設定解析キャッシュを持つ。ミューテックスだけでは外部起動されたOBSを検出できないため、定期探索を単純に削除しない。Process.Exitedによる監視変更は、手動起動・複数OBS・終了直後の再起動・アクセス拒否を含む検証と、実測に基づいて次の段階で判断する。

JSONの手書き簡易パース、Win32への全面書き換え、SetWinEventHook、CIキャッシュ、LTOは今回導入しない。配布文書・アイコン資源の整理とREC表示の遅延生成も別の変更とする。すでに安定しているオーバーレイの都度生成・解放と、Studio Modeの250ms安定待ちは維持する。
