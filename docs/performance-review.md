# 高速化・軽量化の優先修正（2026-10-19）

対象は0.1.4からの作業ブランチ `feat/performance-hardening`。優先順位は、昇格・起動依頼の安全性、継続的なファイル肥大、重複I/O、録画準備の反復処理、表示の不具合とした。main・Release・PCへはまだ反映していない。

## 今回の修正

- 導入：管理者確認後にユーザー書き込み可能なスクリプトを再読しない。すでに読み込んだコピー用関数だけをEncodedCommandで渡し、コピー元DLL・localeは確認待ちから終了まで読み取りロックする。診断ファイルも開いたまま保持し、取消・失敗時はハンドルと一時ファイルを解放する。起動アシストの導入・起動は従来どおり通常権限。
- 起動依頼：同じディレクトリの一時ファイルへ完全な内容を書いてから公開する。既存ファイルの置換もアトミックに行い、例外時は一時ファイルを削除する。PID・期限・一度だけ消費する検査は維持。
- ログ：256KiBで切り替え、旧ログは1世代だけ。旧版で大きくなったファイルも末尾256KiBだけを残し、1メッセージは4096文字までに制限する。現在のログは最後の1メッセージ分だけしきい値を超え得る。
- 設定：実際の保存先の内容と一致する場合、書き換えない。メモリ上の成功キャッシュだけには頼らず、外部変更・削除・保存失敗後の再試行を扱う。設定画面の保存コールバックは参照する所有者を明示する。
- 初回応答：FINISHED_LOADING後、最初のイベントループで依頼を確認する。見つからなければ従来の500ms周期へ戻し、60秒の期限と終了時の解除を維持する。
- ウィンドウ録画：準備中はHWND/PIDと表示状態を軽く確認。OBSソースが取得したタイトル・クラス・実行ファイルの照合と250msの安定待ちは維持し、重いOBSウィンドウ探索は準備開始時と録画開始直前に行う。
- ホバー：まず表示状態とGetWindowRectで絞り、その候補だけでDWM・タイトル・プロセスの問い合わせを行う。describeの二重呼び出しを解消する。
- 範囲選択：ドラッグ中の物理座標が変わらなければ矩形と説明を再計算しない。画面外・異種DPIの座標変換やEnter確認は変えない。
- REC表示：文字列に必要な大きさが変わった場合だけサイズを調整し、右端へ置き直す。100分・1000分になっても右にはみ出さない。

## 検証の範囲

インストーラーは通常権限の専用一時フォルダーにコピーする隔離テストを使う。実際のUACを承認する試験や、署名済みインストーラーと同等の全体監査をしたものではない。日本語・空白・引用符を含むパス、確認待ち中のコピー元変更拒否、失敗診断・取消・再試行を確認する。

起動アシストの自己テストは通常のWindows環境で成功。制限環境では一時ファイル移動が拒否されたため、制限環境の結果を実環境の動作不良とは扱わない。専用一時フォルダーを使い、常設版やユーザー設定を更新しない。

Windows CIでは実際のQt/libobsを使う既存9テストに回帰条件を追加する。録画準備の重い照合回数、最終照合失敗時の開始禁止、設定の同一内容での更新日時保持、外部変更・削除後の保存、100分以上のREC表示を含む。最新のCI結果はdocs/testing.md末尾に記録する。

処理回数や書き込みの削減を、実機のCPU使用率・メモリ・起動時間の改善率と同一視しない。実録画、各DPI、各キャプチャ方式の再受入と、同一条件での性能比較は未実施。

## 続きの改善（2026-10-20、0.1.5）

REC表示は録画開始時に必要な場合だけ作り、停止後に解放する。配布ZIPから開発用docsとAGENTS.mdを除き、READMEの開発文書リンクはGitHubへの絶対リンクにした。CIの固定SDKキャッシュと、対応するMSVCでのRelease LTOを追加した。ZIPは許可した10ファイルだけを含むことと、ソース・ビルド成果物とのSHA-256一致をCIで検査する。

範囲ドラッグ中のサイズ表示はpaintEventへ移し、QLabelの文字列・レイアウトを毎回変更しない。古い表示位置も再描画範囲に含める。ウィンドウ選択中はGUIスレッドでSetWinEventHookを使用し、変更通知とマウス移動時だけ探索を予約する。登録失敗時は従来の50～250msタイマーへ戻す。確定・モード変更・終了時に解除する。オーバーレイの都度生成・解放と、Studio Modeの250ms安定待ちは維持する。

起動アシストはWin32版を採用した。C++20と静的CRT、OS標準Windows.Data.Json、単一アイコン資源を使用し、常駐プロセスはQt/.NETを必要としない。JSONの手書き解析は行わない。既存設定・起動依頼・Startupリンク・安全な削除方法・同名ミューテックスを維持する。削除時だけ起動するPowerShellヘルパーは.NET標準APIを使い、親プロセスから引き継いだPSModulePathに依存しない。

既知のOBSプロセスは終了ハンドルを待ち、外部起動はQtウィンドウの作成通知、設定はディレクトリ変更通知で検出する。通知登録失敗・プロセスへのアクセス拒否・キー登録失敗では2秒探索へ戻す。起動要求の未消費中だけ500msで確認する。ミューテックスをOBSの存在判定には使わない。

`Native assistant check`はOBS SDK不要でビルド・自己テスト・新旧の隔離ベンチマークを行う。`tests/measure-assistant.ps1`はC#版のコピーから、実キー・通知領域・ユーザー設定・実OBSへのアクセスを除いた比較用EXEを生成する。ネイティブ版も`--benchmark`で専用一時設定を使う。通常アプリは終了しない。報告CPU時間はプロセス起動時からの累積値を含み、純粋な定常CPU使用率や録画の高速化率ではない。

機能修正の最終コミット5000995で、Windows CI 39372161707のネイティブ自己テスト・隔離比較と、39372161640のMSVCビルド・全9テスト・ZIP検査が成功した。このPCでもネイティブ自己テストと60秒の隔離比較を3回実施した。working setは旧版44.68～44.81MiBに対し10.82～10.83MiB、private bytesは30.70～30.88MiBに対し1.52～1.55MiB。ネイティブ版の周期タイマー起動は3回とも0回。CPUは起動からの累積値を含み、定常CPUや実録画速度の改善率には換算しない。通常の通知領域アイコンを表示した実アプリとは測定条件が異なる。

試験で検出した競合も修正した。MoveFileExによる既存依頼の置換は共有読み取り中にアクセス拒否になる場合があり、ReplaceFileと新規作成時のMoveFileExへ分けた。同時読取を伴う100回のネイティブ試験を維持する。StartupリンクはWindowsによるパス表記の正規化を考慮し、実ファイルの同一性で照合する。削除ヘルパーの診断を回収し、PSModulePathに依存するGet-FileHash等を除いた。以前のC#実装はtests/legacy-assistant.csに比較用としてのみ残し、配布しない。

## 2026-10-24 追加改善1〜3

ユーザーの「まず1・2・3」に従い、`feat/selection-notification-performance`で以下を実装した。

## 2026-10-25 追加改善4・5

同じ作業ブランチで残りを実装した。

- 起動依頼は、FINISHED_LOADING後に親フォルダーを監視してから一度確認する。ファイルがまだ存在しない場合と、アトミックなファイル置換にも対応する。通常の空待ちは500ms周期を使わず、60秒の期限だけを持つ。監視登録失敗・フォルダー消失・ロック等で未消費のファイルが残る場合は500ms確認へ戻し、可能になれば通知監視を再登録する。対象PID・期限・サイズ・書式・一度だけの消費は従来の検証を維持する。
- 受信・期限切れ・終了時は監視とタイマーを停止する。QFileSystemWatcher本体はシグナル処理後に破棄し、不要な監視エンジンを残さない。
- 全画面選択は初回とマウス移動・進入時に確認し、高速移動の最終位置を単発タイマーで補う。マウス停止中の250ms確認は行わない。ツールバー・説明ラベルにもマウス追跡を設定し、オーバーレイ内だけのイベントフィルターで処理する。クリック時の最終確認とEnter確定、範囲ドラッグ、ウィンドウ選択の登録失敗時の周期確認は維持する。

回帰テストには、起動前の依頼・後からの作成/置換・異なるPID・ファイルロック解除・取消・期限・監視先の消失/再作成、全画面選択の静止時タイマー停止・子ウィジェット経由の移動・外部ウィンドウの無視を追加した。最終ビルドと実行結果はdocs/testing.md末尾に記録する。CPU・メモリ・体感速度の改善率は未測定。
